# Курс «ERP-CRM системи» — Трек A: Бібліотека / прокат (`library_rental`)

Репозиторій кастомних модулів Odoo 19 (Community) для практичних занять 1–6 курсу **«ERP-CRM системи»**.

## Як запустити середовище (Odoo 19 + PostgreSQL 15+)

### Варіант 1: Через Docker Compose (рекомендовано)
```bash
docker compose up -d
```
Після запуску відкрийте `http://localhost:8069`, створіть порожню базу даних, увімкніть режим розробника (**Settings → Activate the developer mode**), натисніть **Apps → Update Apps List**, знайдіть `Library Rental` (`library_rental`) та натисніть **Activate**.

### Варіант 2: Локальний запуск з вихідного коду Odoo 19
```bash
git clone https://github.com/odoo/odoo.git --depth 1 --branch 19.0 odoo19
python -m venv venv
# Windows: venv\Scripts\activate | Linux/macOS: source venv/bin/activate
pip install -r odoo19/requirements.txt
python odoo19/odoo-bin -r odoo -w odoo --addons-path=odoo19/addons,custom_addons -d library_db --dev=all
```

## Документування роботи з AI-асистентом (Практичне заняття 1, Крок 6)

### 1. Що згенерував AI-асистент

Для підготовки середовища, перевірки роботи AI-асистента у редакторі та генерації базового каркасу модуля `library_rental` було використано такі промпти:

1. **Промпт для перевірки AI-асистента (Крок 3 — пояснення структури `addons`):**
   > *"Поясни структуру стандартного каталогу `addons` у вихідному коді Odoo 19 Community та призначення ключових файлів усередині типового модуля Odoo (`__manifest__.py`, `__init__.py`, `models/`, `views/`, `security/`)."*
2. **Промпт для генерації `.gitignore` (Крок 2):**
   > *"Згенеруй файл `.gitignore` для Git-репозиторію розробки кастомних модулів Odoo 19 на Python 3.11+. Включи ігнорування службових файлів Python (`__pycache__`, `venv`), налаштувань IDE (`.vscode`, `.idea`) та специфічних для Odoo файлів (`filestore`, `sessions`, `.odoorc`, `*.log`, дампів БД)."*
3. **Промпт для генерації каркасу модуля `library_rental` (Крок 4):**
   > *"Створи мінімальний каркас кастомного модуля Odoo 19 у папці `custom_addons/library_rental` для Треку A «Бібліотека / прокат». Модуль повинен містити `__manifest__.py`, кореневий `__init__.py` та порожні пакети `models/` (з `__init__.py`), `views/` і `security/` без жодних моделей (моделі Book, Copy, Member, Loan будуть додані на наступному занятті)."*

### 2. Що ви виправили вручну

Після критичного рев'ю коду, згенерованого AI-асистентом, було внесено такі ручні виправлення у `__manifest__.py` та файлову структуру модуля:

1. **Виправлено формат версії у `__manifest__.py` (`version`):**
   - AI-асистент згенерував скорочену версію `'1.0'` (або шаблон від старішої гілки `'17.0.1.0.0'`).
   - Вручну виправлено на `'19.0.1.0.0'`, щоб суворо відповідати конвенції версіонування Odoo 19 (`19.0.x.x.x`).
2. **Очищено список залежностей (`depends`):**
   - AI-асистент додав «про всяк випадок» зайві модулі `['base', 'mail', 'contacts', 'web']`.
   - Вручну видалено `mail`, `contacts` та `web`, залишено виключно `['base']`. Це відповідає вимогам завдання: на старті читачі ще не прив'язані до `res.partner`, а зайві залежності сповільнюють запуск інстансу та ініціалізацію бази даних, підтягуючи непотрібні таблиці й дані.
3. **Очищено секцію `data` від неіснуючих файлів:**
   - AI-асистент за замовчуванням прописав у `'data'` шляхи `'security/ir.model.access.csv'` та `'views/library_views.xml'`, хоча самі моделі ще не створені.
   - Вручну залишено порожній список `'data': []`, оскільки за наявності посилань на порожні або відсутні файли Odoo видає помилку під час встановлення модуля.
4. **Перевірено та явно задано ліцензію (`license`) і прапорці застосунку:**
   - Додано поле `'license': 'LGPL-3'` (щоб уникнути попередження в логах Odoo 19 про відсутність ліцензії) та встановлено `'application': True`, `'installable': True`, щоб модуль одразу відображався у основному списку застосунків (Apps) за фільтром за замовчуванням.
5. **Перевірено ланцюжок імпортів Python (`__init__.py`):**
   - У кореневому `custom_addons/library_rental/__init__.py` залишено лише `from . import models`, а у `custom_addons/library_rental/models/__init__.py` прибрано згенеровані AI закоментовані/неіснуючі імпорти `from . import book`, щоб пакет `models` коректно імпортувався як порожній Python-модуль без `ImportError`.
   - У порожні каталоги `views/` та `security/` додано файли `.gitkeep`, щоб Git зберіг порожню структуру папок у репозиторії.

## Обґрунтування вибору `depends: ['base']`

У файлі `__manifest__.py` вказано єдину залежність `'depends': ['base']`, тому що:
- Модуль `base` є обов'язковим ядром Odoo (забезпечує роботу ORM `models.Model`, базових полів, прав доступу `ir.model.access`, системних користувачів `res.users` та базового інтерфейсу).
- На етапі Практичного заняття 1 ми створюємо лише чистий каркас без бізнес-моделей. Додавання `contacts` (якщо не використовується розширення `res.partner` прямо зараз), `mail` (chatter/повідомлення) або `sale` лише збільшить час завантаження реєстру модулів і створить зайві таблиці в БД.
